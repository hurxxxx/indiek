- 자동화 서버 주간 보고에 Matomo 읽기 토큰을 연결하고, 게시 직후 Meta 자동 점검으로 보이는 방문을 사람 유입과 분리해 표시한다.
- 매주 같은 표로 기록: Search Console 클릭·노출, 사람 페이지 로드, Threads 링크 클릭, 참여 기능 완료 수.
- 상태(2026-11-09): 집계 스크립트 `scripts/traffic-report.py` 추가, 실행법은 [배포 문서](../deploy/README.md#접속-로그). 기준 주(11/2~11/8)는 사람 페이지 로드 39, 브라우저 환경 27(운영자 확인 포함). 같은 날 자동화 서버 주간 보고에 Matomo 토큰을 연결했다. 최근 30일(10/11~11/9) 동의 방문은 75, 재방문 5, 이벤트는 Acquisition 51·Music 2다. 받은 토큰은 슈퍼유저 권한이며, 사용자 결정으로 그대로 사용한다. - 상태(2026-11-09): 아티스트 페이지 검색 제목·설명(`아티스트 (한국어 이름) — “곡” lyrics meaning`)과 구조화 데이터, 입문 가이드의 검색 제목(`Korean indie music: where to start`)을 로컬에 반영하고 검사를 추가했다. 공유 카드는 바꾸지 않았다. 같은 날 운영에 배포했다(`1ee7ff3`). 사이트맵을 다시 제출해 37개 페이지 읽기 성공을 확인했고(색인 29, 미색인 8), 입문 가이드와 아티스트 10곳(검정치마·최유리·한로로·새소년·유라·백아·김사월·백예린·화이트유즈드삭스·손디아)의 색인을 요청했다. 할당량 초과로 남은 moneto·MRCH 등은 수동 요청 대신 사이트맵 `lastmod`와 자동화 서버의 Search Console API 일일 점검(바뀐 사이트맵 재제출, 전체 URL 색인 상태 확인, 주간 보고 요약)으로 관리한다. 같은 날 서비스 계정을 연결해 첫 점검을 실행했다. 색인 34/37이며 미색인은 MRCH(Google 미인식), moneto와 기사 `black-skirts-everything`(발견됨, 미색인)이다. 11/9 수정 이후 다시 읽히지 않은 페이지는 17곳이다. 첫 문단·목차 개편은 편집 검수가 필요해 곡 페이지(W2)와 함께 진행한다. 2026-11-09 W2와 함께 첫 문단을 `korean indie music` 검색 의도에 맞게 고치고 목차와 아티스트·곡 페이지 링크를 추가했다(`5c59acf`, 같은 날 운영 배포). 곡 페이지가 더해진 뒤 11/10 점검 기준 색인은 34/40이다.

### W2. 곡 페이지 구조 (2~6주, D3)

- 주소: `/artists/<artist-id>/<song-slug>/`. 기존 곡 ID와 `indiek-saved-v1` 저장 목록은 바꾸지 않고, 새 `slug` 필드만 추가한다. 기존 `#listen`·`#track-<id>` 앵커는 유지하고 곡 페이지로 연결한다.
- 구성: 공식 영문·한국어 제목, 작사·작곡·편곡 크레딧, 발매 정보, 공통 플레이어 재생 버튼, 곡 배경(출처 포함), 가사 해설, 비슷한 곡 3개, 아티스트 요약, Apple Music 링크.
- 아티스트 페이지는 곡 목록 허브가 된다. 빌드는 slug 중복, canonical, 사이트맵, 내부 링크를 검사한다.
- 정보가 부족한 곡 페이지는 내용을 채울 때까지 `noindex`로 둔다. 대량 생산 페이지로 보이지 않도록 페이지마다 검증된 고유 정보가 있어야 한다.
- 상태(2026-11-09): 23곡 모두 곡 페이지를 만들고(`slug` 추가, 1~2곡 시안 승인 후 전체 적용) 빌드·검사에 slug 중복·canonical·`noindex`/사이트맵·내부 링크·구조화 데이터 검사를 더했다. 색인 기준은 크레딧·Apple Music·출처 있는 배경·가사 해설을 모두 갖춘 곡이며 현재 3곡(한로로·백예린·MRCH)이다. 나머지 20곡은 정보를 확인해 채우면 색인된다(`node scripts/song-pages.mjs`). 같은 날 운영에 배포했다(`5c59acf`).

### W5. 방문자 참여형 콘텐츠

공유될 결과물을 만들고, 그 결과가 다시 콘텐츠가 되게 한다. 모든 재생은 공통 플레이어 `#persistent-player`를 사용한다. 개인정보 수집과 동의 문구는 출시 전에 [개인정보 안내](https://indiek.com/privacy-and-terms/)(원문은 `scripts/build.mjs`)와 맞춘다.

**1차 · 서버 없이 (4~12주)**

- **K-indie 월드컵:** 16·32곡 토너먼트. 공식 녹음을 들으며 한 곡씩 고른다. 우승곡 결과 페이지는 공유 주소와 곡별 미리 만든 공유 카드를 가진다. 테마별로 반복 출시한다(입문, 밴드, OST, 겨울 등).
- **취향 퀴즈 "Find your Korean artist":** 좋아하는 서양 아티스트·분위기 등 5~6문항으로 아티스트를 추천하고, 결과 카드를 공유한다. 결과는 해당 아티스트·곡 페이지로 연결한다.
- **Saved 목록 공유:** 저장 목록을 주소에 담은 읽기 전용 플레이리스트 페이지. 방문자가 직접 만든 목록이 공유 단위가 된다. 기존 저장 키는 바꾸지 않는다.

### W7. Rust 백엔드 (12월 MVP, 이후 확장)

정적 사이트는 그대로 두고, 참여형 기능에 필요한 쓰기·집계만 같은 도메인의 `/api/`로 제공한다. API가 멈춰도 페이지·재생·Saved는 정상 동작하고 집계 표시만 숨긴다.

- **구성:** axum(tokio) + SQLite(sqlx) 단일 바이너리. 저장소에 `api/` Cargo 크레이트를 두고 `cargo test`를 기존 검증 흐름에 추가한다. 실행·배포 방법은 [README](../README.md)와 [배포 문서](../deploy/README.md)에 둔다.
- **배포:** 운영 웹 서버에서 systemd 서비스로 실행하고 Nginx가 `/api/`만 프록시한다. 같은 출처라 CSP는 `connect-src 'self'`로 충분하다. SQLite는 매일 백업한다. 공유 서버의 기존 서비스(Matomo 등)는 건드리지 않는다.
- **API (MVP, 12월):**
  - `POST /api/polls/{id}/votes`, `GET /api/polls/{id}/results`: 연말 리스너 투표
  - `POST /api/requests`: 곡·아티스트 해설 요청(곡·아티스트 ID나 짧은 텍스트, 이메일은 받지 않음)
- **API (확장, 1~3월):**
  - `POST /api/brackets/{id}/results`, `GET /api/brackets/{id}/stats`: 월드컵 경기별 선택 비율
  - `POST /api/reactions/{trackId}`, `GET /api/reactions?ids=`: 곡 반응과 리스너 인기곡 페이지
- **입력 검증:** 곡·아티스트·투표 ID는 빌드 결과물의 공개 카탈로그와 대조해 없는 ID를 거부한다. 텍스트 요청은 길이를 제한하고 운영자 확인 전에는 공개하지 않는다.
- **개인정보·남용 방지:**
  - IP는 메모리의 요청 빈도 제한에만 쓰고, 날마다 바뀌는 솔트로 해시한 값만 잠시 보관한다.
  - 중복 투표 방지는 브라우저 저장소의 무작위 토큰으로 하며, 쿠키나 계정은 쓰지 않는다.
  - 서버 로그에 원시 IP나 토큰을 남기지 않는다.
  - 출시 전 개인정보 안내에 수집 항목·보관 기간을 추가한다.
- **측정:** 참여 완료 수는 API 집계로 바로 센다. W0 주간 표에 함께 기록한다.
- **동시 접속:**
  - 페이지는 Nginx가 정적으로 제공하고, API는 참여 기능의 쓰기·집계만 받는다.
  - 월 100만 방문에서도 API 쓰기는 평균 초당 1건 미만, 급증 시 수십 건 수준으로 본다.
  - SQLite는 WAL 모드, `synchronous=NORMAL`, `busy_timeout`을 쓴다. 쓰기 연결은 하나로 두고 읽기 연결은 따로 둔다.
  - 반응·월드컵 집계는 카운터 행 UPSERT로 저장하고, 급증 시 메모리에서 1초 단위로 모아 쓴다.
  - 결과 조회는 메모리 캐시와 Nginx 마이크로 캐시(1~5초)로 처리한다.
- **PostgreSQL 전환 기준:** API 서버를 여러 대로 늘리거나 무중단이 필요할 때, 계정·댓글처럼 쓰기가 무거운 기능을 열 때, 다른 호스트가 DB에 직접 써야 할 때. 대비해서 SQL은 표준 문법으로 쓰고 마이그레이션 파일로 관리하며, DB 접근은 한 모듈에 모은다. 백업은 매일 `VACUUM INTO`로 받고, 필요하면 Litestream으로 실시간 복제한다.
- 상태(2026-11-09): `api/` 크레이트에 상태 확인·투표·결과·요청 엔드포인트와 테스트를 만들고 `npm run check`에 연결했다(cargo가 있을 때). 투표 정의는 `content/polls.json`이다. Listeners' Picks 2026은 승인된 설정(12/10 12:00 ~ 1/1 00:00 KST, 최대 3곡, 결과는 마감 후 공개)으로 두고 투표 화면을 공개할 때까지 `draft`로 유지한다. Nginx `/api/` 설정은 `deploy/nginx.conf`에 합쳤다. systemd·백업 절차와 개인정보 안내 초안은 [배포 문서](../deploy/README.md#참여-api)에 있다. 같은 날 사용자 승인 후 운영 웹 서버에 설치했다(`30f85f3`, 서비스 `indiek-api`, 매일 백업). 설치 결과는 [배포 문서](../deploy/README.md#참여-api)에 있다. 11/11 투표 페이지(`/polls/<id>/`)와 요청 페이지(`/request/`)를 main에 합쳤다(`11fc64e`). 투표는 `draft`라 공개 빌드에 나오지 않고, 요청 양식은 API가 응답할 때만 열린다. 11/12 운영에 배포해 요청 화면이 공개됐다(`ac69ab8`).

### W8. AI 운영 에이전트 (D8)

사람이 하던 답글, 커뮤니티 참여, 연락 준비를 AI가 맡는다.

- **시작 분량:** 사람 기준 주 4~6시간이다. 기준은 다음과 같다.
  - indiek 게시물의 댓글·멘션은 모두 응답한다.
  - Threads의 관련 대화에 하루 5~10건 참여한다.
  - Reddit 댓글은 주 2~3건이다.
  - 연락 초안은 주 1~2건이다.
- **확대:** 품질이 확인된 작업부터 범위와 빈도를 넓혀 상시 대응에 가깝게 한다.
- **구현 위치:** 자동화 서버의 공통 게시기(`scripts/promotion/`)에 대화 모듈을 추가한다. 기존 게시와 같은 원격 작성·독립 검수, 공식 API, 큐·이력 구조를 쓴다. 토큰은 서버에만 둔다.
- **승인 방법:** 처음에는 로컬 `promotion:remote` 명령으로 승인 대기열을 보고 한 번에 처리한다. 휴대폰에서 승인하는 화면은 W7 API의 운영자 전용 기능으로 검토한다.
- **상태(2026-11-10):** v1(댓글·언급 응답, 대화 탐색, 승인 대기열, 한도·보류·중단·기록)을 [배포 문서](../deploy/README.md#threads-대화-에이전트-w8-v1)대로 구현해 서버에 반영했다. 답글 읽기·쓰기 권한을 재승인했고 Threads 소개란에 AI 안내를 넣었다. 사용자 요청으로 같은 날 `engage resume go-live`를 실행해 자기 글 답글을 시작했다(하루 4회 점검). 언급·검색 권한은 아직 없다. 직접 OAuth 승인으로 받고, 다른 계정 글을 돌려받으려면 Meta 앱 심사(고급 접근)도 필요하다.

지켜야 할 것:

- **공식 경로만:** 공식 API만 쓰고, 브라우저 자동 조작이나 비공식 자동화는 하지 않는다. API가 지원하지 않는 작업(예: 계정 팔로우)은 대상 목록을 주간 보고에 올리고 사용자가 앱에서 처리한다. Reddit은 API 이용 조건(앱 등록·승인)을 먼저 확인한다.
- **스팸 방지:** 외부 답글은 하루 한도를 두고, 같은 계정에는 주 1회까지만 답한다. 링크는 질문에 직접 답할 때만 붙인다. 같은 문장을 반복하지 않는다.
- **정직성:**
  - 사람 행세를 하지 않고, 청취 경험이나 추억을 지어내지 않는다.
  - 필요한 곳에서는 운영자 계정임을 밝힌다.
  - 프로필에 AI가 답글 작성을 돕는다는 사실을 표시한다.
  - 사실은 공개 페이지와 출처 범위 안에서만 말한다.
- **보류:** 아티스트 사생활, 팬덤 분쟁, 정치, 건강처럼 민감한 대화에는 답하지 않고 보류한다.
- **중단:** 제한·신고·오류가 생기면 해당 작업을 즉시 멈추고, 원인을 기록하기 전에는 재개하지 않는다.
- **기록:** 모든 활동은 [홍보 기록](promotion.md)의 자동 구간에 남긴다. 측정 항목은 답글 수, 승인률, 반응, 프로필 링크 클릭, 팔로워 증가, 신고·제한 건수다.

## 유지하는 원칙
