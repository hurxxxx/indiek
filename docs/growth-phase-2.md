# 성장 2단계 계획 (2027-05 ~ 2027-10)

목표: 2027년 10월 말까지 월 10만 방문. 1단계에서 효과가 확인된 콘텐츠 유형을 10배 규모로 늘리고, 다시 찾아오는 이유(뉴스레터·차트·공연 일정)를 만든다. [1단계 계획](growth-phase-1.md)의 원칙과 측정 방식을 그대로 이어 간다.

## 시작 조건

2027년 4월 말 1단계 평가에서 아래를 확인한 뒤 시작한다. 기준에 못 미치면 2단계 규모를 줄이고 미달 항목을 먼저 고친다.

- 1단계 성공 기준(월 사람 방문 1만, Search Console 월 클릭 4,000)의 70% 이상 달성
- 콘텐츠 유형별 페이지당 월 방문을 비교한 결과. 상위 유형에 투입을 집중한다.
- 확장 파이프라인의 실제 처리량과 검수 오류율(표본 검수에서 사실 오류 2% 이하)
- Search Console 수동 조치·대량 색인 제외 없음

## 작업 흐름

### P2-W1. 카탈로그 1,000명 / 4,000곡

- 아티스트 120명 → 1,000명, 곡 600곡 → 4,000곡. 1단계의 A급(가사 해설)·B급(크레딧·배경·공식 녹음) 구분을 유지하고 A급은 600곡을 목표로 한다.
- 앨범 페이지(`/albums/<album-slug>/`)와 아티스트 디스코그래피를 추가한다. 앨범 수록곡은 곡 페이지로 연결한다.
- 파이프라인 처리량을 주 150곡으로 올린다. 사람 표본 검수는 5~10%로 낮추되 오류율이 2%를 넘으면 처리량을 줄인다.
- 정보가 부족한 페이지는 `noindex`로 둔다. 1단계와 같은 기준을 적용한다.

### P2-W2. K-드라마 OST 상시 운영

- OST 허브를 100편으로 늘린다. Netflix·Disney+·TVING 등에서 해외 공개되는 화제작은 OST 공개 후 48시간 안에 페이지를 낸다.
- OST 가수 페이지를 아티스트 카탈로그에 합친다. 드라마 시청자가 가수와 다른 곡으로 넘어가게 한다.
- 드라마 방영 일정에 맞춘 "이번 주 새 OST" 목록을 홈과 뉴스레터에 넣는다.

### P2-W3. 공연·페스티벌

- 서울 주간 공연 캘린더를 연다. 공연장 공지·예매처를 근거로 하고, 출처와 확인일을 표시한다.
- 여름·가을 시즌(펜타포트 8월, 부산락·그랜드민트·잔다리페스타 가을)의 라인업·아티스트·이동 정보를 가이드로 낸다.
- 공연장 페이지를 30곳으로 늘리고 부산 등 다른 도시 가이드를 추가한다.

### P2-W4. 참여형 콘텐츠 확장 (Rust API)

- **직접 만드는 월드컵:** 방문자가 카탈로그 곡으로 직접 토너먼트를 만들어 공유한다. 곡은 카탈로그 안에서만 고르고, 제목은 길이 제한과 금칙어 검사 후 공개한다.
- **주간 리스너 차트:** 곡 반응·월드컵 선택을 바탕으로 매주 차트를 공개한다. 집계 방식을 차트 페이지에 밝힌다.
- **계절 투표:** 여름 노래, 페스티벌 기대 라인업 등을 분기마다 연다.
- **요청 처리:** 들어온 요청은 2주 안에 반영 여부를 공개 목록에 표시한다.
- API에는 사용자 월드컵 저장, 운영자 검토 대기열, 차트 집계 작업을 추가한다. 운영자 도구는 웹 관리자 화면 대신 CLI로 시작한다. 저장소는 SQLite를 유지한다.

### P2-W5. 재방문

- **주간 뉴스레터 "New Korean music this week":** 신곡, 새 OST, 이번 주 공연, 차트를 담는다.
- 홈에 "이번 주" 영역을 두고 같은 데이터로 만든다.
- Saved 공유 목록을 뉴스레터와 SNS에서 소개한다. 계정 없이 유지한다.

### P2-W6. 유통·파트너십

- **인터뷰:** 매달 2건.
- **레이블 프로그램:** 영어 소개문 제공과 신보 정보 접수 양식을 운영하고, 접수된 정보는 검수 파이프라인으로 보낸다.
- **페스티벌 파트너십:** 잔다리페스타 등 해외 관객이 있는 행사에 영어 미디어 파트너를 제안한다.
- **YouTube 시범 운영(E4):** 주 1편, 허락받은 클립과 직접 녹음한 해설로 만든다.
- **SNS·커뮤니티:** 1단계의 Threads·Reddit 운영을 이어 가고, 참여형 결과를 주 소재로 쓴다.
- **AI 운영 에이전트:** 1단계 승인률을 근거로 자동 범위를 넓힌다. 뉴스레터 답장, 독자 요청 접수 안내, 레이블 신보 접수 확인까지 맡긴다. 사용자 명의의 연락은 계속 승인 후 보낸다.

### P2-W7. 기술 기반

- 증분 빌드: 바뀐 아티스트·곡 페이지만 다시 만든다.
- 사이트맵을 유형별(아티스트, 곡, 앨범, OST, 기사)로 나누고 사이트맵 색인을 둔다.
- 사이트 검색 색인을 나눠 첫 로드 크기를 유지한다.
- 이미지 변환·캐시를 정리한다.
- API와 사이트의 가동 감시, 오류 알림, SQLite 일일 백업 복구 연습을 한다.

### P2-W8. 측정

- 1단계의 주간 표에 콘텐츠 유형별 월간 보고를 더한다. 항목은 페이지당 방문, 재방문 비율, 뉴스레터 클릭, 참여 완료다.
- 생성형 AI 검색 요약 때문에 노출이 늘어도 클릭이 줄 수 있다. 검색 외 유입(직접·뉴스레터·참여·커뮤니티) 비중을 따로 추적한다.

## 점검과 중단 기준

- 페이지당 방문이 하위 25%인 유형은 다음 달 신규 생산을 멈추고 기존 페이지를 개선한다.
- 표본 검수 오류율이 2%를 넘으면 처리량을 절반으로 줄이고 원인을 고친다.
- 뉴스레터 오픈율이 3개월 연속 25% 미만이면 구성과 발송 빈도를 바꾼다.
- 사용자 월드컵 신고나 부적절 제목이 늘면 공개 전 검토로 전환한다.

## 3단계로 넘어가는 조건

- 월 방문 7만 이상, 성장률 월 15% 이상 유지
- 콘텐츠 1건 생산 비용과 페이지당 방문으로 3단계 확장의 비용 대비 효과 추정
- E1(가사 라이선스)·E5(수익화) 결과
- 이 결과로 [3단계 계획](growth-phase-3.md)의 범위와 인력을 확정한다.
